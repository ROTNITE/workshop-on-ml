# Исследование градиентных методов

Главный результат — `regression (2).ipynb`, заново написанный и выполненный notebook внутри этой папки.
В нём **пять основных блоков**, отдельный вывод для шестого слайда и дополнительный блок трёх GIF.
Все вычисления опираются на `regression_data.csv`, лекции и примеры из репозитория пользователя.
Исходный notebook сохранён без изменений в `sources/regression.original.ipynb`.

## Что подготовлено

- `outputs/results.xlsx`: сводные таблицы, 60 конфигураций, F/t-проверки, корреляции, устойчивость отбора, исходные данные и прогнозы. Метрики test в Excel вычисляются формулами из прогнозов.
- `outputs/tables/`: полные CSV, в том числе 28 800 прогнозов LOOCV и принадлежность объектов выборкам.
- `outputs/figures/`: три основных PNG в оформлении исходного notebook, графики сходимости и подбора шага в PNG/SVG.
- `outputs/animations/`: отдельно три GIF с обновлёнными данными. Код их создания сохранён в notebook и `src/animations.py`.
- `outputs/conclusions.md`, `outputs/slide_outline.md`: выводы и материал для пяти слайдов плюс вывода.
- `outputs/best_model.json`: коэффициенты победителя в исходных единицах, достаточные для прогноза `intercept + X @ coefficients`.
- `outputs/selection_before_test.json`: зафиксированный до test выбор метода, шага и признаков.
- `outputs/provenance.json`: seed, конфигурация, версии библиотек и SHA-256 источников.

В Jupyter / VS Code откройте `gradient_study/regression (2).ipynb` и выполните все ячейки сверху вниз в ядре этой среды.
Папка самодостаточна: датасет находится в `data/`, лекции — в `sources/lectures/`.
Завершённый notebook уже содержит результаты; повторный запуск не нужен для просмотра.
Если анимации при пересчёте не требуются, установите `CREATE_ANIMATIONS=False` в первом блоке.
Шрифты графиков: Arial в Windows или DejaVu Sans в Linux. Иначе скрипт явно сообщает об отсутствии шрифта.

NumPy/Pandas/SciPy используются для массивов, таблиц и распределений; scikit-learn — только для разбиения;

nbformat/nbclient/ipykernel нужны для сборки и полного исполнения notebook.
Statsmodels используется только в независимых тестах статистических формул.

## Методика

Разбиение сохранено из исходного notebook: 480 train / 160 validation / 160 test, random_state=42.
Начальный VGD сходится к МНК и сверяется с независимым решением.
F/t и корреляции рассчитываются на train. Признаки выбираются программно; `y` не сокращается.
Проверяются 5 методов × 2 расписания × 6 значений начального шага = 60 конфигураций.
Постоянный шаг — λ; функциональный — λ / sqrt(1+k), как в лекции 2.
В каждой LOOCV обучающей части заново выполняются кодирование, отбор и масштабирование.
Победитель выбирается по MSE validation, затем единственный раз оценивается на test.

Важная граница: LOOCV здесь оценивает всю процедуру, включая повторный отбор признаков.
Поэтому она не равна CV старого notebook, где пять признаков были зафиксированы заранее.
У времени до метро и номера подъезда полная train-модель имеет пограничные p-value;
исключение одной квартиры иногда меняет отбор. Это объясняет рост LOOCV до ~617 тыс. руб.
В отчёте сохранена таблица частоты отбора по folds. Отбор на всём train перед CV
занижал бы оценку неопределённости этой процедуры.

Бюджет 10 000 обновлений одинаков, но вычислительная стоимость обновления у методов разная.
`max_iter` не выдаётся за доказанную сходимость. Победитель SAG исчерпал бюджет;
он выбран за минимальную validation-ошибку именно в этом эксперименте.
Различие с близкими методами мало, поэтому универсального превосходства не заявляем.
Обычные F/t-проверки предполагают корректную линейную модель, независимые ошибки и
постоянную дисперсию; нормальность даёт точные конечновыборочные распределения.
После отбора p-value имеют разведочный смысл. Нулевой p-value в CSV может быть следствием
численного округления очень малой вероятности, а не буквально нулевой вероятностью.
